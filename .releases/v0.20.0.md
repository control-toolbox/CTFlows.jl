## Release proposal — CTFlows v0.20.0 (stable)

**Version.** Last release `0.19.1`; last version in General `0.19.1`. Since `0.19.1`: three breaking changes, new features and fixes. By `REL1` (0.Y.Z: the breaking component is Y) and `REL2` (no beta: the triple `0.20.0` is above every released one), the version is **`0.20.0`**.
**Jump in General (`REL3`).** None.
**Resolves from General alone (`REL4`).** ✅ (CTSolvers 0.7.1 is in General.)
**Versions applied.** ct-agents `v0.5.0` (this recipe), ct-conventions `v0.15.0`, CTActions `dc60661` (the release tool).

### What changes since `0.19.1`

- 💥 `Flow(ocp, law; multipliers=:label => μ)` replaces `constraint=` and `multiplier=` (#543, PR #545).
- 💥 The accessors of a flow lose the `get_` prefix; a flow and its solution share `switching_times` and `phase_labels` (#544, PR #546).
- 💥 A trajectory integrated backward is returned in increasing time; the objective of a backward trajectory is the cost of the arc (#547, PR #549).
- ✨ A multi-phase flow integrates any horizon (after the first switching time, before the last, in a single phase, backward); `variable_costate=true` on the point call of a Hamiltonian multi-phase flow; `Trajectories.in_increasing_time`; `n_phases(f) == 1` on a single flow.
- 🐛 A multi-phase flow no longer returns a wrong value, silently, on a horizon that does not contain the switching times in order; the derivative with respect to a switching time is right under ForwardDiff.
- 📦 `CTSolvers` compat `0.7.1`.
- 🧪 📚 Exact initial costate `p(0) = -0.99` in the tests and docs of #440 (PR #548).
- Not in `[Unreleased]` yet, added by the release PR: none (#542 is a formatter run).
- Open PRs, not in this release: none.
